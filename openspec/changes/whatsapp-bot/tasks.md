## Carried validator findings (baked into tasks — do not lose)

1. **ORDER**: provider layer (tasks 1.6–1.9, PR4) lands BEFORE its consumers (templates 2.x, dispatch 3.x, webhook 4.3, bot 5.4) — dependency lines enforce it. Resolves design.md:490-491 listing ambiguity (WU-4/WU-3 order): consumers depend on 1.9.
2. **Lockout reset-on-expiry**: `failed_attempts` MUST reset when a 24h lockout expires before the next failure is counted (task 5.4), so `failed_attempts <= 3` CHECK (pg 23514) can never fire 500 — soft lockout is windowed per spec (max 3 failed attempts per 24h).
3. **Audit action decision**: `bot_message.sent` is REQUIRED (spec message+audit atomicity for outbound); `bot_conversation.identification_failed` is an explicit implementer decision (mirror design — recommended, or drop) — record the choice in apply notes so verify aligns (task 5.4).
4. **Phone pass semantics**: migration SQL pass MUST mirror `phone-normalizer.ts` rules exactly so collision-skipped rows are predictable; every skipped row logs its rationale (`SKIP<collision|no_heuristic>`); migration spec asserts skips match normalizer predictions (tasks 1.4, 1.5).
5. **First-attempt increment timing**: `send_attempts` increments when a send attempt STARTS — initial insert routes `queued` with `send_attempts=1`; retry re-routes `queued` with `send_attempts += 1` BEFORE the provider call (crash-consistent with max-3, task 3.2).
